\section{Problem Description}
A mid-sized industrial company operates across multiple regions and needs to determine where to build or lease storage and distribution facilities to service all client business while incurring the minimum operational cost possible for the business. The company has a fixed set of client sites (factories, plants \& distributors) that require regular shipments of raw materials and finished goods. There is also a fixed set of candidate sites where the company can build or lease storage facility locations each of which can serve clients within a defined coverage radius. The core question is: 

\begin{quote}
    What is the minimum number of storage facilities required to cover all client sites, and where are they located in order to minimize the total operational cost?
\end{quote}

The core idea behind this problem is to find an optimal solution to a real world problem faced by distribution companies like logistic providers, pharmaceutical companies, and industrial part suppliers. Solving it optimally determines both capital expenditure and long-term operational efficiency required to meet client demand while reducing operational costs.

\subsection{Formal Problem Definition}
Given the inputs defined above, the B2B Distribution Problem can be formally stated as the following optimization problem:

\[
    \min_{S \subseteq F}\ \sum_{f_j \in S} o_j
\]

Subject to the following constraints:
\begin{itemize}
    \item \textbf{Coverage constraint:} $\forall\, c_i \in C,\ \exists\, f_j \in S : d(c_i, f_j) \leq R$, where $d(\cdot,\cdot)$ is the Euclidean distance between two coordinate points.
    \item \textbf{Budget constraint:} $\displaystyle\sum_{f_j \in S} o_j \leq B$
    \item \textbf{Selection constraint:} $S \subseteq F$
\end{itemize}

In other words, we seek the least-cost subset of candidate facilities that (a) places every client site within the reach radius of at least one selected facility, and (b) keeps the total operating cost within the available budget.

\subsection{NP-Hardness: Reduction from Set Cover}
The B2B Distribution Problem is NP-hard. We establish this via a polynomial-time reduction from the classic NP-complete \textit{Set Cover} problem. Informally, the hardness arises because selecting the cheapest covering subset forces a search over all $2^m$ candidate subsets, with no known polynomial-time shortcut, leading to combinatorial explosion as the number of facilities grows.

\subsubsection{The Set Cover Problem}
Given a universe $U = \{u_1, u_2, \ldots, u_n\}$ of $n$ elements, a collection of subsets $\mathcal{S} = \{S_1, S_2, \ldots, S_m\}$ with $S_j \subseteq U$, and a positive integer $k$, the Set Cover decision problem asks: does there exist a sub-collection $\mathcal{S}' \subseteq \mathcal{S}$ with $|\mathcal{S}'| \leq k$ such that $\bigcup_{S_j \in \mathcal{S}'} S_j = U$? This problem is NP-complete.

\subsubsection{Set Cover $\leq_p$ B2B Distribution}
Given an arbitrary Set Cover instance $(U, \mathcal{S}, k)$, we construct a B2B instance in polynomial time as follows:

\textbf{Instance transformation:}
\begin{enumerate}
    \item For each element $u_i \in U$, create a client site $c_i$ placed at coordinates $(i,\, 0)$ in a 2D plane.
    \item For each subset $S_j \in \mathcal{S}$, create a candidate facility $f_j$ with uniform operational cost $o_j = 1$, positioned at the centroid of the client sites $\{c_i : u_i \in S_j\}$.
    \item Set the reach radius $R$ large enough so that facility $f_j$ covers client $c_i$ if and only if $u_i \in S_j$.
    \item Set the budget $B = k$.
\end{enumerate}

\textbf{Correctness:} The B2B instance has a feasible solution of cost $\leq B = k$ if and only if the Set Cover instance has a cover of size $\leq k$.
\begin{itemize}
    \item ($\Rightarrow$) If a set cover $\mathcal{S}' \subseteq \mathcal{S}$ of size $\leq k$ covers all of $U$, the corresponding facilities $\{f_j : S_j \in \mathcal{S}'\}$ cover all client sites in the B2B instance. Since each $o_j = 1$, the total cost equals $|\mathcal{S}'| \leq k = B$, satisfying both the coverage and budget constraints.
    \item ($\Leftarrow$) If a B2B solution $S^* \subseteq F$ of cost $\leq B = k$ covers all clients, then $|S^*| \leq k$ (since each $o_j = 1$). The corresponding subsets $\{S_j : f_j \in S^*\}$ therefore form a set cover of size $\leq k$ for $U$.
\end{itemize}

This transformation runs in polynomial time in $|U|$ and $|\mathcal{S}|$. Therefore, Set Cover $\leq_p$ B2B Distribution, which implies the B2B Distribution Problem is NP-hard.

The exact brute-force approach will guarantee finding the optimal solution but may be computationally infeasible for larger instances of the problem due to its exponential time complexity. On the other hand, the greedy approximation algorithm will provide a solution that is not guaranteed to be optimal but can be computed efficiently, making it suitable for larger instances of the problem. We will analyze the time complexities of both approaches and compare their performance on relatively small test cases to evaluate their effectiveness in solving the B2B Distribution Problem.

\section{Algorithmic Approaches}
Throughout this section, we will discuss two algorithmic approaches to solve the B2B Distribution Problem, the first being an exact brute-force approach which is guaranteed to find the optimal cheapest solution, and the second being a greedy approximation algorithm which is tasked with leveraging a heuristic to find a solution that is not guaranteed to be optimal, but is computationally efficient and can be used for larger instances of the problem. Following the discussion of these two approaches, we will analyze their time complexities and compare their performance on various test cases.

\subsection{Exact Brute-Force Approach}
The exact brute-force approach to solving the B2B Distribution Problem involves enumerating all possible subsets of candidate facility sites and checking which subsets cover all client sites while minimizing the total operational cost. The algorithm is found in the file \texttt{brute-force.py} and can be summarized as follows:

\begin{enumerate}[label=\textbf{Step \arabic*.}]
    \item Generate all possible subsets of candidate facility sites.
    \item For each subset, check if its total sum of operational costs is within the budget, and if it is less than the current minimum cost found. This is a preemptive check to avoid unnecessary coverage checks for subsets that are already too expensive thus saving time.
    \item If the subset is within budget, check if all client sites are covered by the facilities in the subset. This is done by using a precomputed coverage matrix that indicates which client sites are covered by which candidate facility sites based on the reach radius.
    \item If all client sites are covered, update the minimum cost and the corresponding subset of facilities if the cost is lower than the previously recorded minimum cost.
\end{enumerate}

\subsubsection{Time Complexity Analysis}
The time complexity of the exact brute-force approach is exponential in the number of candidate facility sites, as it requires checking all possible subsets of candidate facilities. Specifically, if there are $m$ candidate facility sites, there are $2^m$ possible subsets to evaluate. For each subset, we need to check if it covers all client sites, which can be done in $O(n)$ time where $n$ is the number of client sites. Therefore, the overall time complexity of the brute-force approach is $\Theta(n \cdot 2^m)$, making it impractical for large instances of the problem.

\subsection{Greedy Approximation Algorithm}
The greedy approximation algorithm for the B2B Distribution Problem is designed to find a solution that is not guaranteed to be optimal but can be computed efficiently. The algorithm is found in the file \texttt{greedy.py} and can be summarized as follows:
\begin{enumerate}[label=\textbf{Step \arabic*.}]
    \item Initialize an empty set of selected facilities and a set of uncovered client sites.
    \item While there are still uncovered client sites:
    \begin{enumerate}[label=\textbf{\alph*.}]
        \item For each candidate facility site, calculate the cost-effectiveness ratio, which is defined as the number of uncovered client sites that would be covered by selecting that facility divided by its operational cost.
        \item Select the candidate facility site with the highest cost-effectiveness ratio and add it to the set of selected facilities.
        \item Update the set of uncovered client sites by removing those that are now covered by the newly selected facility.
    \end{enumerate}
\end{enumerate}

This is the conventional greedy approach to the Set Cover Problem, which is known to have a logarithmic approximation ratio. In the context of the B2B Distribution Problem, this means that the cost of the solution found by the greedy algorithm will be at most $O(\log n)$ times the cost of the optimal solution, where $n$ is the number of client sites. This is because the greedy algorithm prioritizes facilities that cover the most uncovered client sites per unit of cost, which is a common heuristic for set cover problems; placing emphasis on cost-effectiveness helps to ensure that the algorithm makes efficient choices in terms of coverage and cost despite not guaranteeing an optimal solution.

\subsubsection{Time Complexity Analysis}
The time complexity of the greedy approximation algorithm is polynomial in the number of candidate facility sites and client sites. Specifically, in each iteration, we need to calculate the cost-effectiveness ratio for each candidate facility site, which takes $O(m \cdot n)$ time where $m$ is the number of candidate facilities and $n$ is the number of client sites. Since we may need to select up to $m$ facilities in the worst case, the overall time complexity of the greedy approximation algorithm is $\Theta(m^2 \cdot n)$, which is significantly more efficient than the exponential time complexity of the brute-force approach.

From $m = 8$ to $m = 18$, the runtime grew from $0.122\,ms$ to $117.202\,ms$, a factor of approximately $961\times$ over 10 steps, closely matching the expected $2^{10} = 1024$. \section{Conclusion}
Overall, the B2B Distribution Problem is a real-world problem that is NP-hard due to its nature of optimization that directly relates to the Set Cover with a cost component. The exact brute-force approach guarantees finding the optimal solution but is computationally infeasible for larger instances due to its exponential time complexity. In contrast, the greedy approximation algorithm provides a practical near optimal solution with significantly improved computational efficiency, making it suitable for larger instances of the problem. Overall the trade-off between optimality and efficiency is evident in the performance comparison, where greedy algorithms can yield solutions that are close to optimal while being computationally feasible, especially as the size of the problem increases. This highlights the importance of approximation algorithms in solving NP-hard problems in real-world scenarios where exact solutions may not be practical.
